# RESET-02 Email Verification Link Fix

**Status:** `PASS` (deployed; fresh inbox resend skipped by operator — account already verified)

## Root cause

EaziAICall generated a correct canonical URL:

`https://eazi-ai-call.vercel.app/verify-email?token=<TOKEN>`

Direct navigation verified successfully. Gmail click rewriting via `https://www.google.com/url?q=...` failed in the operator environment with `ERR_CONNECTION_CLOSED`. That hop is external to EaziAICall.

## Fix

Backend (`auth-email-content.ts` + `auth.service.ts`):

- Canonical URL via `URL` / `URLSearchParams` (`buildAuthAppLink`)
- HTML **Verify email** CTA button (`target="_blank" rel="noopener noreferrer"`)
- Visible copy/paste fallback of the complete canonical URL
- Multipart **text/plain** with the same canonical URL
- No google.com / shortener / tracking redirects generated by EaziAICall
- HTML-escaped href/text
- Idempotent already-verified revisit of a consumed token returns success (single-use preserved)

Frontend (`verify-email/page.tsx`):

- Still reads `token` from query only (no referrer/Gmail dependency)
- Clearer guidance if a link is invalid/expired after already verified
